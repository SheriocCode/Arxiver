安装与启动

  1. 在下载页获取 Arxiver Setup vX.exe，双击按向导安装（可选择安装目录）。
  2. 启动后即为桌面应用，无需浏览器扩展、无需单独启动任何服务。
  3. 关闭窗口只是收进托盘：应用继续在后台运行（翻译任务不中断），窗口会从任务栏消失。想再打开点托盘图标（单击即可），或再启动一次 Arxiver（会唤起已有窗口）；要彻底退出用托盘菜单里的「退出」。

翻译引擎

翻译开箱即用：内置本地翻译模型（HY-MT + llama.cpp）在本机离线运行，无需 API Key；有 NVIDIA 显卡走 GPU，无独显自动回退 CPU。

  • 「设置 → 翻译引擎」可切换为在线接口（OpenAI 兼容），或调整本地模型的 GPU 层数 / 额外参数。
  • Arxiver 助手使用独立的在线接口，在「设置 → AI 助手」配置（与翻译互不影响）。

本地翻译与版面识别均在本机完成，数据不出本机；仅在线接口与 Arxiver 助手会访问你配置的服务。

导入与阅读

  • 「新建文献」可导入本地 PDF，或粘贴 arXiv 链接/编号自动下载。
  • 文库支持分类、标签、星标、回收站、阅读历史与全文检索（标签页 / 年份 / 状态等）。
  • 双击条目打开阅读器（默认原文 + 单页）：工具栏可切换 原文 / 对照 / 译文 与 单页 / 双页，并支持缩放、目录大纲、缩略图与页面主题（护眼 / 米黄 / 暗色）。
  • 工具栏右端的块框按钮（层叠图标）可直接在阅读界面显示 / 隐藏段落块框，没有译文时不可用；点击块框会钉住它，查看对应的原文 / 译文。

翻译

  • 在阅读器工具栏点「翻译」（有译文时为「已翻译」）→ 右侧下拉可设 源语言 / 目标语言 / 导出格式（双语对照 / 仅译文）/ 页数，也可「重新翻译」。
  • 「已翻译」的下拉会列出该文献的多个译文版本，可切换；同一菜单里的「导出译文文件…」把当前译文另存为 PDF。
  • 翻译过程中顶部显示进度（已完成页数 / 当前页块进度）；可取消。翻译在后台继续，切换标签页不会打断，关闭该文档的标签页才会取消。
  • 相同 PDF 与参数再次翻译会命中本地缓存。

Arxiver 助手

右侧「Arxiver」标签是基于文库（可选联网）的对话式助手：

  • 自动路由：默认针对当前文章；涉及其它文献或整库问题时自动检索，必要时会向你追问。
  • 引用跳转：引用文库内容时给出 第 N 页 胶囊，点击跳转到原文。
  • @ 引用：在输入框输入 @ 选择其它已打开文献作为额外上下文（跨文献对比）。
  • 选中文本提问：在 PDF 里选中文字 → 点「问 Arxiver」。
  • 写操作需确认：改元数据 / 标签 / 星标 / 回收站 / 分类、导入论文、增删笔记等，都会先弹出确认卡片（批准 / 修改 / 拒绝）。
  • 长任务有反馈：搜索、读正文、导入下载会显示「正在执行 …」、当前阶段与已用时间；回答按到达顺序显示，中间的过程结果可折叠。
  • 会话自动保存；右上角可查看历史（含关联论文，可搜索）。切换详情标签页不会丢会话。

联网搜索

在「设置 → AI 助手 → 联网搜索」里开启（默认关闭），并填当前服务商的 API Key：

服务商 特点 申请地址
Tavily 英文 / 学术结果更干净，支持学术域名加权；读正文（extract）也用它，按 credits 计费 tavily.com
博查（Bocha） 国内网络友好、响应快，中文网页结果好；学术场景噪声略多，不显示 credits open.bochaai.com
  • 检索范围：学术优先（对 arXiv / 会议 / 期刊等域名加权，不排他）或 全网。
  • 两家的 Key 各自保存在本机，切换服务商不用重填。
  • 开启后助手可以：
    • 搜索：结果以卡片列出（标题 / 站点 / 年份 / 摘要片段 / 链接）。有 arXiv 编号或 DOI 的条目可点卡片上的「导入到文库」入库，其它只能「打开链接」；
    • 读正文：在给结论之前把最相关的网页 / PDF 读进来（通常每轮挑 2~3 篇），用正文里的方法和数字作答，而不是凭搜索片段猜；
    • 引用：回答里指代卡片时显示灰色的 卡片 N 胶囊，点击会滚动到那张卡片并高亮。
  • 「已读正文」行显示读了哪个站点、多少字；悬停可看读取途径（服务端抽取 / 直接抓取）与完整链接，点 ↗ 用浏览器打开。
  • 隐私：只把检索式发给搜索服务商，不上传本地文献内容；读正文时只发送要读的网址。
  • 检索与读取记录会写进运行日志（左侧栏「日志 → 系统运行日志」里搜 websearch，或看 %APPDATA%\Arxiver\logs\app.log）。
  • 联网结果不在本地文库，所以助手给的是链接而不是页码引用。

设置

「设置」包含：翻译引擎（本地 / 在线）、通用、外观（主题 / 字号）、引用、AI 助手（对话接口 + 联网搜索）、同步与存储、快捷键、关于（版本与检查更新）。

数据与存储

本机数据位于 %APPDATA%\Arxiver\：

storage/
  index.json                 # 文库元数据（条目 / 分类 / 标签 / 历史）
  <docId>/                   # 每个条目一个文件夹
    paper.pdf                # 原始 PDF
    <cacheKey>.dual.pdf      # 双语译文
    <cacheKey>.mono.pdf      # 仅译文
    <cacheKey>.blocks.jsonl  # 块框数据
    text.json                # 全文检索用文本
  conversations/             # Arxiver 会话
config.json                  # 设置（含联网搜索开关、服务商与 API Key，明文）
logs/app.log                 # 运行日志（检索 / 读取 / 错误）

更新

应用内置自动更新（electron-updater）：启动时自动检查，也可在「设置 → 关于 → 检查更新」。更新只下载变化的块，未变的大文件（如引擎）不会重复下载；下载完成后点「重启并安装」。

故障排查

  • 翻译失败：本地模式下确认 engine/llama 运行时与 engine/models 模型齐备（安装包已内置）；也可在「设置 → 翻译引擎」切换为在线接口并填写地址 / 密钥 / 模型。阅读器顶部会显示错误。
  • 首次翻译较慢：首次会自动加载本地模型并缓存字体 / 版面模型（约数秒），之后变快。
  • 翻译引擎：本地模式下翻译时才会启动 Python 引擎（python.exe），任务结束就退出；本地模型服务（llama-server.exe，约 1.4 GB）首次翻译后常驻，所以后续翻译主要是每页的版面分析 + 翻译 + PDF 写回，另有每次任务约 2 秒的引擎启动固定开销。每次翻译的分段耗时（引擎就绪 / 版面模型加载 / 版面分析 / 全流程）会自动记进「日志 → 系统运行日志」，也可在「运行状态」面板看到引擎进程与任务。
  • 源文件缺失：条目对应的 storage/<docId>/paper.pdf 丢失时无法打开，需重新导入。
  • 助手无响应：确认「设置 → AI 助手」的接口地址 / 密钥 / 模型正确、网络可达，且已在「AI 助手」中启用。
  • 联网搜索不生效：确认已在「设置 → AI 助手 → 联网搜索」打开开关，并且填的是当前服务商的 Key（切到博查后要填博查的 Key）；两家 Key 都留空时搜索不可用，「读正文」也只剩本机抓取。
  • 搜索报错：Key 无效 / 额度用尽 / 请求过于频繁会直接在回答里说明；可以换服务商或换检索式再试。
  • 读正文失败：需要登录或纯前端渲染的页面可能读不到，助手会说明；给它 PDF 直链（如 arxiv.org/pdf/…）通常可行。
  • 任务管理器里的数字和「运行状态」面板不一样 / 那几个 “Arxiver” 分别是什么：两件事一起说。① Windows 任务管理器只按 exe 的「描述」显示进程名，Chromium 的渲染 / GPU / 网络等子进程在它那里全都叫 Arxiver（只有 Chrome / Edge 这类被系统特殊识别的浏览器才显示「GPU 进程 / 工具进程」），用面板里的 PID 就能逐行对上。② 数字不一样是因为列的”口径”不同：任务管理器「进程」页默认那列是「活动的专用工作集」，Chromium 不提供这个数；面板给的 工作集 / 提交大小 分别对应任务管理器「详细信息」里可添加的「工作集(内存)」「提交大小」两列（已逐进程核对一致）。所以要看数字，请在任务管理器切到「详细信息」→ 右键表头 → 选择列，勾上这两列（顺便勾「命令行」还能看到 --type=…）。应用内左侧 「运行状态」 面板另有整体内存 / CPU 趋势、「暂停」采样和「导出诊断报告」（进程快照 + 环境信息 + 最近日志，方便发给开发者排查）。面板底部 「翻译引擎与任务」 单独列出主进程的子进程（Python 引擎 python.exe、本地模型服务 llama-server.exe：PID、内存、端口、正在翻的文件）与任务进度——这些不在 Electron 的进程表里，任务管理器里也是另一个进程名，所以不列在上面。另外注意：多开文献标签或同时翻多篇不会新增进程，所有文书都渲染在同一个界面进程里，翻译任务则是排队跑同一个 Python 引擎。
