工作原理

Electron 桌面应用：渲染进程（React）负责界面与 PDF.js 渲染，主进程负责文库/存储、调用内嵌的本地翻译引擎（Python）与模型接口。

导入 PDF ─▶ 文库 storage/<docId>/paper.pdf
打开 ─▶ 渲染进程用 PDF.js 渲染原文 / 译文（对照）
点翻译 ─▶ 主进程调用内嵌引擎（engine/）─▶ 你配置的 OpenAI 兼容模型
        └▶ 生成 dual/mono PDF + blocks.jsonl，落盘到 storage/<docId>/
Arxiver ─▶ 主进程检索 storage/*/text.json（BM25）+ 读正文，调用模型流式作答

组成

目录 说明
electron-app/src/main/ 主进程：引擎调度、文库/存储、Agent（模型 + 工具 + 审批）、自动更新
electron-app/src/renderer/src/ 渲染进程：React 组件、styles.css、PDF 阅读器引擎、Arxiver 面板
electron-app/src/preload/、src/shared/ window.api（IPC）与共享类型
electron-app/engine/ 随应用分发的本机翻译引擎（Python）
icons/、site/→docs/ 品牌资源与文档站

数据格式

数据都在用户目录 %APPDATA%\Arxiver\：storage/index.json（文库元数据）、 storage/<docId>/（paper.pdf、<cacheKey>.dual.pdf、<cacheKey>.mono.pdf、<cacheKey>.blocks.jsonl、 text.json）、storage/conversations/（Arxiver 会话）、config.json（设置）。详见文档。

Arxiver 助手

  • 模型：OpenAI 兼容 chat/completions（流式、function calling、usage），读取 config.json。
  • 只读工具：list_library、search_library、read_document、search_in_document（基于 text.json 的 BM25）。
  • 写入工具：update_metadata、apply_tags、set_flags、move_to_trash、restore_from_trash、add_to_collection —— 均需用户在确认卡片中批准。
  • 智能路由：当前文章为默认上下文，跨文献/整库问题自动检索；信息不足时追问。

更新与发布

  • 打包：electron-builder（NSIS）。发布由人工执行：powershell -File tools/publish.ps1 -Version X.Y.Z， 产出安装包、.exe.blockmap、latest.yml 并上传到 GitHub Release。
  • 更新：electron-updater 读取 latest.yml，差量下载（只下变化块）；引擎文件未变不会重下。
  • 引擎版本记于 electron-app/engine/VERSION；引擎有实质更新时 bump 并在 changelog 注明。

构建

cd electron-app
npm install
npm run dev        # 开发运行
npm run typecheck  # tsc（node + web）
npm run build      # electron-vite 构建
npm run dist       # 打包安装包（electron-builder）

第三方许可

  • PDF.js（Mozilla，Apache-2.0）：PDF 渲染与文本层。
  • PyMuPDF（Artifex，AGPL-3.0）：引擎文本抽取。
  • KaTeX（MIT）、react-markdown / remark / rehype（MIT）：Arxiver 回答渲染。
  • 图标集移植自 Lucide（ISC）。
